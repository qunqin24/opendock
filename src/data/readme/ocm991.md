# ocm991

Локальный плагин памяти для [opencode](https://opencode.ai): даёт агенту долговременную память проекта — факты, предпочтения и решения, накопленные в прошлых сессиях, автоматически попадают в контекст новых сессий, а модель может сохранять новое через инструменты `memory_save` / `memory_list`.

Идея агентской памяти не нова — есть несколько похожих систем. Этот плагин отличается от аналогов тем, что:

- **редактирует секреты на входе** — ключи и токены заменяются отпечатком до записи на диск (у большинства аналогов редактирование секретов нет вовсе);
- **хранит память вне репозитория** — в каталоге данных пользователя, а не внутри проекта, откуда её можно случайно закоммитить;
- **защищает записи кросс-процессным локом** — параллельные сессии opencode не затирают друг друга;
- **не даёт модели произвольного кода** — инструменты памяти работают без режима code execution;
- **не имеет ни одной runtime-зависимости и не ходит в сеть**.

Общие черты с аналогами — fail-open хуки, дедупликация фактов, перечитывание снапшота после компакции — в этом плагине реализованы самостоятельно.

Ключевые свойства:

- **Локально и приватно** — памяти хранятся в каталоге данных пользователя, никакой сети и внешних сервисов; секреты (ключи, токены) редактируются на входе и на диск не попадают.
- **Переживает компакцию** — снапшот памяти перечитывается после сжатия контекста, модель не теряет знания в длинных сессиях.
- **Устойчивость к сбоям** — любой сбой хранилища не роняет сессию (fail-open), записи атомарны и защищены кросс-процессным локом.

## Установка

Основной путь — штатная команда opencode:

```sh
opencode plugin add ocm991
```

Команда сама скачает пакет и запишет его в конфиг opencode (`~/.config/opencode/opencode.json` для всех проектов или `opencode.json` в корне проекта) — в канонический массив `plugins`. После перезапуска opencode инструменты памяти доступны в сессии.

Ручная альтернатива — добавить имя пакета в массив `plugins` конфига вручную; при следующем запуске opencode сам скачает пакет:

```json
{
  "plugins": ["ocm991"]
}
```

Легаси-ключ `"plugin"` не используйте: хост его ещё читает, но `plugin update` и `plugin check` матчатся только против массива `plugins` — подключение через `"plugin"` не покрывается штатным обновлением.

Память хранится в каталоге данных пользователя — `$XDG_DATA_HOME/opencode-memory` (по умолчанию `~/.local/share/opencode-memory`) — вне репозитория проекта. Плагин читает и пишет этот каталог напрямую, поэтому opencode разрешение на него не спрашивает; запрос появится, только если модель сама полезет туда встроенными инструментами opencode — такой доступ настраивается в `permissions.external_directory`.

## Обновление

Обновление до последней опубликованной версии:

```sh
opencode plugin update ocm991
```

Если установлена актуальная версия, обновлений нет: команда ответит «No plugin updates available» и ничего не изменит. Указывайте пакет голым именем `ocm991` без пинирования версии (голое имя соответствует `latest` в реестре): литерал в конфиге определяет, какой пакет матчат `update` и `check`. Скачанные копии пакета кэшируются в `~/.cache/opencode/npm/ocm991@latest/<ts>`, где `<ts>` — метка времени установки.
