# trackxai plugins

Plugins that connect a coding agent to [trackxai](https://trackxai.kalebtec.com), an agent-native task tracker.
Version 0.1.2. MIT licensed. Release notes are in [CHANGELOG.md](CHANGELOG.md).

This repository is generated by the trackxai release pipeline. A change made here is overwritten by the next
release.

## Install

The Claude Code and Codex plugins install from this repository. Sign in with your browser: there is no token to
paste. The token fallback and the profile directory for each harness are in the table below.

### Claude Code

In a terminal, run:

```
claude plugin marketplace add kalebteccom/trackxai-plugins
claude plugin install trackxai@trackxai
```

Then start Claude Code, run `/mcp`, pick `trackxai` and sign in with your browser. Inside a session, the same two steps
are `/plugin marketplace add kalebteccom/trackxai-plugins` and `/plugin install trackxai@trackxai`.

- Check: `claude mcp get plugin:trackxai:trackxai`
- Pin this release: `claude plugin marketplace add kalebteccom/trackxai-plugins#v0.1.2`
- Update: `claude plugin marketplace update trackxai`, then `claude plugin update trackxai@trackxai`
- Remove: `claude plugin uninstall trackxai@trackxai`, then `claude plugin marketplace remove trackxai`

### Codex

In a terminal, run:

```
codex plugin marketplace add kalebteccom/trackxai-plugins
codex plugin add trackxai@trackxai
codex mcp login trackxai
```

The last command opens your browser on trackxai.

- Check: `codex mcp list`
- Pin this release: `codex plugin marketplace add kalebteccom/trackxai-plugins --ref v0.1.2`
- Update: `codex plugin marketplace upgrade trackxai`, then `codex plugin remove trackxai@trackxai` and
  `codex plugin add trackxai@trackxai`
- Remove: `codex plugin remove trackxai@trackxai`, then `codex plugin marketplace remove trackxai`

### The other harnesses

OpenCode and Pi install from npm, where 0.1.0 of each is published. Hermes Agent installs by copying files.

| Directory       | Harness                                              | Install                                                                                                     |
| --------------- | ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `opencode`      | OpenCode                                             | npm package `@trackxai/opencode`: add it to the `plugin` list in `opencode.json`                          |
| `pi`            | Pi                                                   | npm package `@trackxai/pi`: `pi install npm:@trackxai/pi`                                                  |
| `hermes`        | Hermes Agent                                         | Merge `mcp_servers.trackxai.yaml` into `config.yaml`, and copy `trackxai/` into the plugins directory       |
| `agent-plugins` | The `trackxai login` command and a helper for the above | npm package `@trackxai/agent-plugins`, published                                                                                                      |

## Sign-in, tokens and profile directories

Every plugin installs into, and reads from, the active harness profile. Set the variable to run a harness under another
profile.

| Harness | Sign-in | Token, as the fallback | Profile directory |
| --- | --- | --- | --- |
| Claude Code | `/mcp`, pick `trackxai`, sign in with your browser | Export `TRACKXAI_TOKEN`, then add a user-scope server of the same name with `claude mcp add-json` | `$CLAUDE_CONFIG_DIR`, else `~/.claude` |
| Codex | `codex mcp login trackxai` | Export `TRACKXAI_TOKEN`, then set `bearer_token_env_var = "TRACKXAI_TOKEN"` on `[mcp_servers.trackxai]` in `config.toml` | `$CODEX_HOME`, else `~/.codex` |
| OpenCode | `opencode mcp auth trackxai` | Export `TRACKXAI_TOKEN` before OpenCode starts | `~/.config/opencode/`, or `$OPENCODE_CONFIG` (a file) and `$OPENCODE_CONFIG_DIR` |
| Pi | `trackxai login --harness pi` | Export `TRACKXAI_TOKEN`, which wins over the `trackxai.env` the login writes | `$PI_CODING_AGENT_DIR`, else `~/.pi/agent` |
| Hermes Agent | `hermes mcp login trackxai`, after merging the block | Swap in the commented token entry of the block, and put `TRACKXAI_TOKEN` in the `.env` in the profile directory, never in `config.yaml` | `$HERMES_HOME`, else `~/.hermes` |

A token comes from the Agent tokens page of your workspace. Keep it out of any file in a repository.

## What is here

| Directory       | Holds                                                                                  |
| --------------- | -------------------------------------------------------------------------------------- |
| `claude-code`   | The Claude Code plugin, and its marketplace entry at `.claude-plugin/marketplace.json`  |
| `codex`         | The Codex plugin under `codex/trackxai`, and its entry at `.agents/plugins/marketplace.json` |
| `opencode`, `pi`, `hermes` | The OpenCode, Pi and Hermes Agent plugins                                |
| `agent-plugins` | The `trackxai login` command and the registration helper the Pi and OpenCode plugins import |

The Claude Code, Codex and OpenCode plugins name the trackxai server by URL and nothing else. The harness signs you
in through its own MCP OAuth, so no file here holds a token. Pi and the Hermes token fallback take a token by reference, never as a
value. The [trackxai setup page](https://trackxai.kalebtec.com/mcp-setup) lists the same sign-in, token and profile lines per harness.
