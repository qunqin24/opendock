# opencode-stretch

Адаптация [cc-stretch](https://github.com/pro-vi/cc-stretch) (MIT, pro-vi) для OpenCode 2.
Ответы приходят компактными; фрагменты с деталями раскрываются по клику и сворачиваются обратно. Модель получает сведения о раскрытых фрагментах в следующем запросе как ограниченную телеметрию.

## Как работает

- Серверный плагин (`src/index.ts`) через `context`-хук добавляет модели инструкцию выпускать блоки:

  ````markdown
  ```stretch
  v1 <серверный токен хода> <метка блока>
  Текст с {{краткая форма|подробная форма}} фрагментами.
  ```
  ````

- TUI-плагин (`src/tui.ts`) показывает обычный абзац без рамки и фона. Подчёркнутая голубая краткая фраза заменяется подробным текстом по клику; `«` сворачивает её обратно. Остальной текст не кликабелен. Вложенные фрагменты раскрываются независимо, перенос пересчитывается при изменении ширины.
- Используются только публичные OpenTUI API (`StyledText`, `lineInfo`, нативное измерение ширины) и общий рантайм хоста. Патчей Markdown, приватных полей и глобального рендера нет; граница поддерживаемого fenced-блока остаётся.
- Клик по фразе → RPC `resolveBlock`/`recordOpened` → серверная проверка по транскрипту сессии и долговременная запись раскрытия (идентичность — канонический кортеж, не хеш текста; изоляция сессий и папок).
- Следующий запрос модели содержит телеметрию: какие фрагменты были раскрыты. Сворачивание запись не стирает.

## Состав

- `src/core/` — парсер `{{краткая|подробная}}`, извлечение блоков из Markdown, каноническая идентичность.
- `src/server/` — транскрипт-проверка, состояние, инструкция модели.
- `src/rpc.ts` — строгий RPC-контракт между TUI и сервером.
- `tests/` — 13 тестов (парсер, изоляция, идентичность, E2E телеметрии).
- `.host-test/` — изолированная среда проверки на реальном хосте (не для коммитов).

## Установка и проверка

Для native OpenTUI FFI нужен Node.js не ниже 26.4.0. Ambient Node может быть старее: локальная dev-зависимость Node 26.12.0 используется только для тестов. Установите зависимости, включая платформенный бинарник:

```sh
npm install
npm run lint
npm run typecheck
npm test
```

`npm test` запускает Vitest под `node_modules/node/bin/node`, чтобы тесты использовали Node с `node:ffi`. Обычные команды Node в системе не изменяются.



## Релизы

Conventional Commits + [release-please](https://github.com/googleapis/release-please): пуш в `main` открывает релизный PR (CHANGELOG, версия); тесты запускаются на релизном PR и на релизном коммите (Node 26 для нативного FFI OpenTUI). Слияние релизного PR создаёт тег, GitHub Release и публикует пакет `@rvboris/opencode-stretch` в npm (trusted publishing, `--provenance`). Типы коммитов: `feat:` → minor, `fix:` → patch, `feat!:`/`BREAKING CHANGE:` → major.

## Подключение

Сервер: `opencode.jsonc` → `plugins` (абсолютный путь к папке проекта, корневые входы `index.ts`/`tui.ts`).
TUI: `cli.json` → `plugins`. Требуется перезапуск OpenCode.

## Ограничения

- Подтверждено на OpenCode 2.0.28; поведение других версий не проверялось.
- Вне TUI (OpenChamber и др.) блоки отображаются как исходный код — интерфейс только терминальный.
- Телеметрия — данные UI, не подтверждение прочтения человеком; границы и формулировки ограничены сервером.
- `STRETCH_DEBUG=1` включает отладочное логирование RPC в TUI.
- Не проверялось вручную: смена темы и переходы между сессиями (автотесты и PTY-проверка пройдены).
