## Overview

一般的なマルチエージェントシステムでは、中央のオーケストレーターが全エージェントの役割を把握しながらタスクを委任します。しかしこの設計は、エージェント数の増加とともにオーケストレーターの判断負荷が増大するという問題を抱えています。また、全サブエージェントとのやり取りがオーケストレーターの同一コンテキスト上で行われるため、コンテキストウィンドウの汚染・肥大化が起こりやすく、長期タスクにおける精度低下の要因となることが知られています。

Argosはこれらの問題を緩和するために開発されたOpenCode向けのマルチエージェント・オーケストレーション・システムです。オーケストレーターは「どのエージェントに頼むか」ではなく「どんなタスクか（タグ）」だけを指定し、エージェントの選択はArgosが担います。

## Quick Start

### 1. 前提条件
- **Bun** がインストールされていること
- **OpenCode** がインストールされていること

### 2. セットアップ & 起動
以下の2ステップで導入が完了します。

```bash
# インストールと構成（対話型ウィザード）
bunx @nest4869/argos install

# OpenCodeの起動
opencode
```

## Agents
Argosは、役割に特化した以下の12種類のビルトインエージェントを提供しています。

| 名称 | 役割 |
| :--- | :--- |
| `orchestrator` | 複雑なタスクに対するプランニングと、スペシャリストエージェントへの自動委譲を担当 |
| `architect` | システム設計、技術ブループリント、スキーマ、実装計画の作成を担当（コードの実装は行わない） |
| `coder` | 中規模な機能開発、アルゴリズムの実装、設計に基づいたリファクタリング（10〜500行程度）を担当 |
| `designer` | UI/UXのデザインと実装、スタイリング、レスポンシブデザイン、コンポーネント設計を担当 |
| `explorer` | コードベースの高速検索とパターンマッチング、ファイルやコードパターンの特定を担当 |
| `fixer` | 単一ファイルに対する超高速な修正・編集に特化したスペシャリスト |
| `general` | ドキュメント作成、設定、プロジェクトのメンテナンスなどのユーティリティタスクを担当 |
| `librarian` | 外部ドキュメントやライブラリの調査、公式ドキュメントやGitHubのコード例の検索を担当 |
| `oracle` | orchestratorが直接相談できる唯一の技術参謀。設計判断やデバッグ支援を担当（タスクとしては実行されない） |
| `refactorer` | 継続的なコンテキストを必要とする複雑なマルチファイルのリファクタリングを担当 |
| `reviewer` | セキュリティ、ロジック、クリーンコードの動機に基づくコード品質の監査を担当 |
| `tester` | テストスイートの生成と実行、コードの正確性の検証を担当 |
