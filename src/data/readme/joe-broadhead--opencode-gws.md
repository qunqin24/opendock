# Google Workspace

Google Workspace for OpenCode: Gmail, Calendar, Drive, Docs and Sheets, with plans and per-class commits. The plugin
is built for a pinned, verified `gws` 0.22.5 executable against each account's own Google sign-in. The `v0.0.0`
package carries `manifest/native.json`, and its release assets carry the verified `gws-<target>.gz` files. It never
calls a `gws` found on `PATH`, and it ships no OAuth client.

## Install

```sh
opencode plugin add github:we-the-rebel-alliance/gws-plugin#v0.0.0
```

The install tag is `v0.0.0`; the lead's release bot cuts it after merge. The plugin needs Node 24 and
OpenCode `>=2.4.1 <2.5.0`; it is tested on `2.4.1`. A release outside that range is refused with `HOST_UNTESTED`; a
release inside the range starts, and status reports it as untested.

On the first call that needs the `gws` executable, the plugin downloads and verifies the pinned 0.22.5 build from its
`v0.0.0` release assets. `binary.path` can name an absolute system copy instead.

## Sign in

Each account is one OpenCode integration: `gws` for the default account, `gws-work` for an account named `work`. In
`/connect`, choose **Google Workspace** (or **Google Workspace (work)**), paste a Desktop OAuth client's ID and secret,
and approve the scopes. One client can serve every alias.

Headless profiles read a credentials file or an access token from the environment variable their profile names; they
need no browser. See [docs/accounts.md](docs/accounts.md).

```json
{
  "options": {
    "accounts": {
      "work": { "enabledServices": ["gmail", "calendar", "drive"] },
      "personal": { "mode": "access_token", "enabledServices": ["drive"], "tokenEnv": "GWS_PERSONAL_TOKEN" }
    }
  }
}
```

## Options

The full options table is generated in [docs/configuration.md](docs/configuration.md). The common ones:

| Option | Default | Meaning |
|---|---|---|
| `access` | `all` | `all`, `ask-changes` or `read-only` |
| `accounts` | one `default` | one profile per alias |
| `allowUntestedHost` | `false` | start outside `>=2.4.1 <2.5.0` |
| `services` | every enabled service | the model-facing service allowlist |

## Access

`access` is the ceiling for every method. A read runs at every level; a change runs under `all`, asks under
`ask-changes` and is off under `read-only`. Every change is still a plan for its class — `plan_write`, `plan_send`,
`plan_share`, `plan_delete`, `plan_export` or `plan_admin` — followed by the matching `write`, `send`, `share`,
`delete`, `export` or `admin` commit. The plan previews the redacted command, its recipients and Google's dry-run answer;
the commit takes only its `planId`.

## Troubleshooting

- **`HOST_UNTESTED`**: the running OpenCode is outside `>=2.4.1 <2.5.0`. Install a supported release, or set
  `allowUntestedHost: true` if you accept an untested host. An in-range release such as 2.4.2 starts and `status`
  reports it as untested.
- **`NEEDS_SIGN_IN`, `SCOPE_MISSING`**: run `/connect`, choose the account's integration and approve every scope. A
  read-only sign-in cannot approve a write; sign in again and choose Read and write.
- **`ACCOUNT_REQUIRED`, `ACCOUNT_UNKNOWN`**: pass `account` with one of the aliases `status` lists.
- **`GWS_UNAVAILABLE`, `BINARY_TRUST_FAILED`**: the first-use download was refused, or the configured `binary.path` is
  not a trusted 0.22.5 executable. Remove a bad cached copy under the plugin cache, or point `binary.path` at a copy
  only you can write.
- **`PLAN_INVALID`, `PLAN_USED`**: plan again and show the new preview; check the current state with `read` before
  repeating a committed change.
- **`PERMISSION_DENIED`**: a deny-only policy rule, the admin gate or the session's rules refused the call. Tell the
  user; do not rephrase the call to get around it.
- **`UNAVAILABLE`**: the provider, the `gws` process or a guard failed. Retry once; if it persists, read `status` and
  the audit log.
