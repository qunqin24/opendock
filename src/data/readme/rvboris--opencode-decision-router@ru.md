# @rvboris/opencode-decision-router

[English](README.md) · [Русский](README.ru.md)

Плагин **OpenCode V2** классифицирует задачи, делегированные субагентам, через API «decisions» (по умолчанию OpenRouter Microsoft Decision) и направляет дочернюю модель на `omniroute/light` или `omniroute/heavy`. JavaScript ESM, без серверных runtime-зависимостей, Node.js >= 18. Установка: `npm install @rvboris/opencode-decision-router`.

**Только V2.** Маршрутизация выключена по умолчанию и включается явно в конфигурации. Интеграция с OpenCode/OMO проверялась локальными mock-сценариями; реальные API-вызовы и их ограничения описаны в [VALIDATION.md](VALIDATION.md). Автоматические переносимые тесты ниже не требуют установленного OpenCode/OMO и не обращаются к платным API.

## Необязательные профили модели и effort

Добавьте `profiles` из [examples/profiles.json](examples/profiles.json) в конфигурацию маршрутизатора, чтобы выбирать модель и уровень effort за один вызов классификатора. Без `profiles` сохраняется поведение `models.light` / `models.heavy`. Пример включает `light_medium`, `light_high`, `heavy_high`, `heavy_xhigh`. Каждый профиль содержит `model` (полный `provider/model#variant`), `label` (`light` или `heavy`), `effort` (`medium`, `high`, `xhigh`) и непустое `description`, используемое как критерий классификации. ID должен совпадать с `label_effort`; variant цели должен соответствовать effort. Имя provider/model задаётся отдельно от метки. Поддерживается любое непустое подмножество сочетаний метки и effort; четыре записи — лишь примеры, не встроенный allowlist. Профили low/max/ultra автоматически не добавляются.

Классификатор предпочитает качество при неопределённости, но не всегда выбирает максимальный effort. Принимаются только профили из конфигурации; произвольные параметры модели из ответа не используются. В `event.input.model` задаётся полная цель вместе с `#variant`. Дополнительные поля профиля отсутствуют в legacy-режиме. Для resume в OMO передавайте полную модель с variant уже маршрутизированного дочернего сеанса вместе с его ID. Локальная проверка mock-проводов подтверждает сериализацию SDK, но не поддержку effort на стороне реального upstream.

### Требования к конфигурации OMO

Управляемые маршрутизатором агенты OMO (например, fixer и explorer) должны использовать `inheritModelFrom: "session"` без скалярного `model` в эффективной конфигурации. Удалите скалярные закрепления модели из активных presets и слоёв override, а также из конфигурации нативных агентов. Иным агентам и оркестратору можно оставить фиксированные модели. Иначе OMO может вернуть дочернюю задачу к модели своего профиля до инференса. При ошибке классификации и наследовании модели от сессии применяется модель родителя, а не фиксированный профиль специалиста.

Для завершённого дочернего сеанса, управляемого OMO, перед native resume сначала получите/подтвердите результат через `task_result`. Передавайте существующую полную модель вместе с variant и ID сеанса. Resume не запускает повторную классификацию.

## Установка и включение

Установите пакет в среду OpenCode:

```sh
npm install @rvboris/opencode-decision-router
```

Пакет содержит серверный плагин и готовую TUI-сборку. Пакет добавляется в OpenCode V2 как непосредственно загружаемая директория; укажите абсолютный путь к установленной директории (для npm это обычно `node_modules/@rvboris/opencode-decision-router`), не создавая wrapper-модуль:

```jsonc
{
  "plugins": ["/absolute/path/to/node_modules/@rvboris/opencode-decision-router"]
}
```

Корневой `index.js` переэкспортирует `src/index.js` и нужен проверенному загрузчику директорий V2; одного поля package exports для активации плагина недостаточно.

Конфигурация JSON задаётся абсолютным путём в окружении:

```sh
export OPENCODE_DECISION_ROUTER_CONFIG=/absolute/path/to/config.json
```

Если переменная не задана или пуста, хуки не устанавливаются и плагин не влияет на работу. При отсутствующем файле, неверном JSON или ошибке валидации маршрутизация безопасно отключается; в stderr записывается только мета-сообщение, содержимое файла не выводится. Полный пример: [examples/config.json](examples/config.json).

## Конфигурация

| Поле | По умолчанию | Описание |
|---|---|---|
| `enabled` | `false` | Главный переключатель; для установки хука требуется `true`. |
| `endpoint` | `https://openrouter.ai/api/alpha/decisions` | Настраиваемый URL. Требуется HTTPS; HTTP разрешён только для loopback-тестов (`localhost` / `127.0.0.1`). Учетные данные в URL запрещены. |
| `apiKeyEnv` | `OPENROUTER_API_KEY` | Настраиваемое имя переменной среды с bearer-ключом. |
| `apiKeyFile` | `null` | Необязательный абсолютный путь к файлу ключа. Читается, только если переменная ключа не задана; допускается один однозначный токен. |
| `decisionModel` | `microsoft/microsoft-decision-1` | Модель для запроса классификации. |
| `models.light` / `models.heavy` | `omniroute/light` / `omniroute/heavy` | Две цели классификации в legacy-режиме. |
| `agents` | explorer, librarian, fixer, oracle, designer, observer | Список имён субагентов, которым разрешено менять модель. |
| `timeoutMs` | `5000` | Целое от 1 до 60000; ограничивает весь запрос, включая чтение ответа. |
| `maxTaskChars` | `4000` | Целое от 1 до 16000; текст задачи (или запасное описание) обрезается до отправки. |
| `logFile` | `null` | Необязательный абсолютный путь; содержит только структурированные метаданные JSONL. |

Передаётся необязательный bearer API-ключ через `OPENROUTER_API_KEY` (или имя, указанное в `apiKeyEnv`). Не записывайте ключ в конфиг/лог.

## Правила маршрутизации

Классификация пропускается (событие остаётся без изменений), если инструмент не `subagent`, имя агента отсутствует в allowlist, задан `input.sessionID` (resume существующего дочернего сеанса сохраняет модель) либо явно выбрана модель вне настроенной пары light/heavy (включая её variant). Variant настроенных light/heavy-моделей повторно классифицируются, позволяя заменить исходное закрепление.

Текст задачи ограничивается `maxTaskChars`. Только корректный ответ с `answers.routing.type === 'choice'` и `choice` строго равным `light` или `heavy` меняет `event.input.model`; остальные аргументы сохраняются. Любая ошибка — отсутствие ключа, сеть, таймаут, HTTP-ошибка, redirect или некорректный ответ — оставляет событие без изменений (fail-open). Повторных запросов нет.

## Экспорты

- `default` — плагин V2 `{ id: 'decision-router', async setup(ctx) }`.
- `createRouter(config, dependencies?)` — тестируемое ядро с `handleEvent`, `evaluateEvent`, `config`; зависимости `fetchImpl`, `now`, `log` можно подменить.
- `loadConfigFromEnv`, `loadConfigFile`, `validateConfig`, `resolveApiKey`, `parseApiKeyFileContent` — загрузка и проверка конфигурации/ключа.
- `evaluateEvent`, `parseModelId`, `validateDecisionResponse` — правила и проверка результата.
- `classifyTask`, `buildDecisionRequest`, `ConfigError`, `DecisionsRequestError`, `DEFAULTS` — клиент и константы.
- `@rvboris/opencode-decision-router/tui` — отдельная TUI-точка входа.

## Конфиденциальность

- На настроенный endpoint отправляется только ограниченный текст делегированной задачи — не история сеанса и не файлы. Обрезка не гарантирует удаление секретов: сама задача может содержать чувствительные данные. Функция явно opt-in.
- Ключи не записываются в логи/ошибки; redirect отклоняются, поэтому ключ не пересылается на другой адрес.
- `logFile` содержит метаданные решения, не prompt, ключ или тело ответа. Не добавляйте лог в публичные артефакты.

## TUI: статистика маршрутизации

В нативной TUI откройте команду **Decision Router: статистика**. Отдельное прокручиваемое окно не меняет footer. **Tab** переключает текущий сеанс и все сохранённые записи; **R** перечитывает журнал; **↑/↓** прокручивают; **Esc** закрывает. Показываются сохранённые записи, модели, effort, агенты, доли и диагностика недоступных/неверных логов. Это статистика сохранённого JSONL, а не полная история OpenCode; пропуски не журналируются, поэтому число пропусков, стоимость, токены и факт upstream-инференса не выдумываются. Сборка TUI: `cd tui && bun run build`.

## TUI: индикатор решения

TUI-точка входа показывает в footer последнего записанного агента и выбранный класс модели (например, `DR · librarian → heavy`), fallback либо локальные состояния выключенной/недоступной конфигурации. Имена моделей/provider, confidence, задержка, пути и тела ошибок не выводятся. Старые записи без имени агента отображаются как `агент неизвестен`, ничего не угадывается. Индикатор остаётся видимым до первого решения; наличие локальной переменной/конфига само по себе не доказывает, что серверный плагин активен. При смене сеанса старый результат сразу очищается.

Индикатор читает `logFile` из env-конфига, обновляется по событиям жизненного цикла и раз в 2 секунды, а при dispose удаляет слот, слушатели и таймер. TUI использует хостовые `@opencode/plugin`, `@opentui/core`, `@opentui/solid` и `solid-js` как внешние необязательные peer dependencies, чтобы не дублировать экземпляр хоста. Сборка и автоматические проверки не доказывают, что реальный клиент загрузил TUI-расширение или показал footer; визуальная проверка отдельно не выполнялась.

## Тесты и выпуск

Переносимые офлайн-проверки (Node.js 18+, Bun для сборки TUI):

```sh
npm ci
cd tui && bun install --frozen-lockfile && bun run build && cd ..
env -u OPENCODE_DECISION_ROUTER_CONFIG npm test
npm run test:pack
```

`npm test` выполняет unit-тесты, интеграционные проверки на локальном loopback и тесты fixtures/runner. Сетевые платные API и установленный OpenCode/OMO не используются. Mock-проверка матрицы хоста запускается отдельно через `node scripts/integration.mjs`; реальные API-тесты через `node scripts/real-validation.mjs` не входят в переносимый CI.

Выпуск ведёт Release Please на ветке `main`: conventional commits создают/обновляют release PR с версией, changelog и manifest. CI отдельно проверяет этот PR; его слияние создаёт GitHub Release. Только событие созданного Release (`release_created`) запускает публикацию npm с provenance через GitHub OIDC. При первой отправке кода пакет не публикуется. Перед выпуском вручную настройте npm Trusted Publishing: на npmjs.com в **Publishing access** добавьте GitHub Actions publisher с owner `rvboris`, repository `opencode-decision-router`, workflow `.github/workflows/release-please.yml`, environment — none. Workflow GitHub требует `contents: write`, `pull-requests: write` для Release Please и `id-token: write` для OIDC-публикации; npm token secret не применяется.
