# opencode-v2-ponytail-scoped — русская версия

> **Ponytail теперь по адресу: «пиши минимум» получает каждый агент на своём уровне — или не получает вовсе, если его не назвали.**

Ponytail для OpenCode V2 с уровнем **на агенте**. English: [README.md](README.md).

## Что именно сделано

Взяты три вещи: (1) — официальный плагин ponytail, только для V1 API; (2) пакет-адаптер `@filecrop/opencode-ponytail-v2`, который перенёс ponytail на V2 API, не трогая тексты; (3) модель многоагентной работы, где параллельные сессии не должны делить один глобальный флаг уровня.

Собран самостоятельный пакет на V2 API:

- **Вендоренный контент upstream** (правила, 6 скиллов, 6 команд, билдер текста) лежит копией 1:1 в `vendor/upstream/` — тексты правил мы не переписываем, лицензия MIT, версия зафиксирована в `UPSTREAM_VERSION`;
- **гейт по агенту**: хук `session.hook("context")` читает `event.agent`, находит уровень в таблице `~/.config/opencode/ponytail-scoped.json` и внедряет правила **только названным агентам**, последним блоком в system prompt;
- **уровень на агенте, а не один на всех**: `coder: full`, `build: lite`, `team/*: ultra`, остальные — чистый промпт;
- **команда `/ponytail` теперь адресная**: пишет переопределение по агенту текущей сессии в state-файл, а не в глобальный флаг; `/ponytail off coder` выключает конкретную роль;
- **отказоустойчивость**: битый или отсутствующий конфиг = `off` = правил нет; сессия не ломается никогда;
- проверки: `node --test` (юнит-тесты на разрешение уровней, конфиг, контракт хука) и `node probe/probe.mjs parity` (посимвольная сверка текста правил с адаптером).

## Какую задачу решает

В мультиагентной настройке ponytail нужен не всем: кодеру — «пиши минимум», планировщику и ревьюеру — лезть руками и сомневаться, одноразовому помощнику — вообще не мешать. И адаптер, и upstream дописывают правила **каждой** сессии, а уровень хранят в одном глобальном флаге: включил «ленивость» в сессии кодера — она включилась у всех, включая параллельные сессии. Это молчаливая протечка стиля инструкций: модель никогда не скажет, что перестала быть дотошной по чужой команде.

Пакет решает ровно одну задачу — **адресность**: правила приходят только тем агентам, которым положены, и на том уровне, который назначен им, а не всем сразу.

## Отличие от других и преимущества

| | upstream ponytail | `@filecrop/opencode-ponytail-v2` | этот пакет |
|---|---|---|---|
| API OpenCode | V1 (на 2.x не грузится) | V2 | V2 |
| Кому правила | всем сессиям | всем сессиям | только названным агентам |
| Уровень | один глобальный флаг | один глобальный флаг | на агенте + переопределения по сессии |
| Тексты правил | источник истины | копия 1:1 | копия 1:1, проверка parity |
| Зависимости в рантайме | — | — | нет |

Преимущества:

1. **Тишина по умолчанию** (`default: "off"`): никто не получает правила, пока его не назвали.
2. **Совместность с параллельными агентами**: уровни не перетекают между сессиями.
3. **Честный vendor**: никакого расхождения текстов с upstream — оно проверяется машиной.
4. **Ноль зависимостей**, пакет работает из папки, клона или npm одинаково.
5. **Поломка конфига безопасна**: худший исход — `off`, никогда — исключение в сессии.

Сознательные ограничения: семантика `/ponytail` изменена (адресная запись вместо глобального флага) — это и есть вся добавленная функциональность; опции из строки конфига `plugins` в `ctx` не приходят (проверено живьём), поэтому настройка — файлом.

## Как применять

1. В `~/.config/opencode/opencode.jsonc` в `plugins` убрать/выключить адаптер и поставить наш пакет **последним** среди плагинов, пишущих в system:
```jsonc
"plugins": [
  "-@filecrop/opencode-ponytail-v2",
  "opencode-v2-ponytail-scoped"        // или абсолютный путь к чекауту
]
```
2. Создать `~/.config/opencode/ponytail-scoped.json`:
```json
{ "default": "off", "agents": { "coder": "full" } }
```
3. Перезапустить OpenCode (`opencode service restart`; при редактировании конфигов плагин перезагружается и без рестарта).
4. Проверить: в сессии `coder` правила ponytail есть (они последние в system), в остальных — нет.

Дальше — обычная работа с ponytail: `/ponytail ultra` усилит **текущего** агента, `/ponytail off coder` выключит роль, таблица `agents` решает всё статически. Скиллы (`ponytail-review`, `-audit`, `-debt`, `-gain`, `-help`) доступны как обычно.
