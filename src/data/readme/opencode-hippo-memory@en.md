# 🧠 HippoMemory (English)

> English summary. Full docs: [Chinese user guide](docs/USER-GUIDE.zh-CN.md) · [Architecture](docs/ARCHITECTURE.md) · [Roadmap](ROADMAP.md)

**Hippocampus-inspired long-term memory for AI agents.** Fights the classic long-session failure mode: context overflow → forgotten facts → hallucination.

```
plain long context (no memory):   0/8 correct, 25% confabulation
HippoMemory-backed:               8/8 correct,  0% confabulation
```
*(bench/anti-hallucination-bench.mjs, 60 noise turns)*

Local-first, zero external services: SQLite via Node's built-in `node:sqlite`, optional local embedding model (~24MB). No cloud, no network, no API keys.

## Packages

| Package | What | Install |
|---|---|---|
| **dsh-hippo-memory** | DSH plugin — memory tools, automatic digest injection, usage guidance, GUI settings page (host DSH ≥ 0.1.7) | `dsh plugin --profile web add dsh-hippo-memory` |
| **opencode-hippo-memory** | opencode plugin — same 4 memory tools + per-turn digest, compression survives. **The V2 plugin face starts at 0.4.0 (the V1 face was deleted by ruling rather than kept beside it); 0.3.3 and earlier are V1 and load nothing on opencode 2.x**, and opencode 1.x is no longer supported | `opencode plugin add opencode-hippo-memory` (V2; the old `-g` form belongs to the V1 command surface) |
| **hippo-memory-core** | Framework-agnostic engine (use in any agent loop) | `npm install hippo-memory-core` |

The engine and the DSH adapter are on npm at **0.3.3**, the opencode adapter at **0.4.0** (the three packs stopped moving in lock-step at this batch: the V2 port touches only that package, so `hippo-memory-core` and `dsh-hippo-memory` stay where they are — `latest` for the first two was set 2026-10-06; the batch content is **0.3.2**, published the same day one step before the status sweep, and npm cannot overwrite an existing version — so `0.3.3` re-issues documentation only, its code members byte-identical to 0.3.2; the line before this batch was engine + opencode 0.3.0, DSH adapter 0.3.1). **`opencode-hippo-memory` is the exception to reading those numbers as "what the host loads": its V2 face is published as 0.4.0 while 0.3.3 and earlier are the V1 face, which opencode 2.x does not load at all — see the row above and the package README's install section.** `dsh-hippo-memory` 0.3.1+ requires **host DSH ≥ 0.1.7** (that release exists solely to follow 0.1.7's new configuration surface); stay on `0.3.0` for an older host. Engine **0.2.1** added **Bun support**: the SQLite driver is detected at load time (`node:sqlite` on Node, `bun:sqlite` on Bun), so `hippo-memory-core` imports and runs inside Bun hosts such as **opencode** (verified on opencode 1.18.31 / Bun 1.3.14: remember, recall, verify, digest and diagnostics all work — no bundling, no shims). `sqliteDriver` tells you which driver is active; `setSqliteDriver()` lets you plug your own. Upgrade: `dsh plugin --profile <profile> update dsh-hippo-memory`, then restart the profile. Stores need **no migration**.

⚠️ After installing an adapter, **restart the host and verify by side effect** (does a `.db` appear in the store directory after one turn?) rather than by config echo: `opencode debug info` (a V1 command — on v2 `opencode debug` has only `agents` / `config` / `paths`, and the plugin surface is `list` / `add` / `check` / `update` / `remove`) only prints configuration anyway, and a failed plugin load can leave zero log lines behind.

## 🆕 0.3.2 (batch 2026-09-25, **published to npm 2026-10-06** — engine + DSH + opencode, all three `latest` tags moved; the same-day `0.3.3` is a docs-only re-issue whose code members are byte-identical) — both of `verify`'s exits need an anchor

Four defects, all in `memory_verify` — the last gate whose whole job is to stop confabulation. D1/D2 came from the tenth field-report round, whose conclusion was "even a yes has to be checked against `support.id` by hand". R1/R2 came from an **independent re-test of 0.3.2 installed in DSH Desktop**, which confirmed D1/D2 pass as a two-sided differential and then reported two residuals. What all four share: the verdict no longer asks "did anything clear the recall floor?", it asks "is there an **anchor**?" — on the yes exit *and* on the contradiction exit.

- **D1 — a topical match used to be stamped as support.** With one row in the store about which language the backend is written in, `verify("Python 是用来煮咖啡的")` answered `substantiated: true` at score 0.47 — **below the `claimThreshold` of 0.75 this same store publishes** in `diagnostics().thresholds`. The verdict answered "did anything clear the *recall* floor (0.32)?" while the tool promises a claim-level answer, and a stamped hallucination is worse than no answer: the model stops going back to the source once it holds a `substantiated`. Raising the floor was measured and rejected: in the hashing space the hallucination scores claim-to-summary **0.444**, and so does a legitimate Chinese paraphrase of the same fact (a verbatim restatement is 1.000, an English paraphrase 0.775). The number cannot tell "restatement" from "same topic" — an **anchor** can, so a yes now needs at least one: same parsed subject with a non-clashing value; a shared identifier (ticket id / sha / version); the trace carrying the claim verbatim (normalized equality, or containment in `summary + detail`); the trace carrying ≥ `claimThreshold` of the claim's distinctive tokens; and only then claim-to-summary cosine ≥ 0.75. **An anchor is not enough either**: the gate is `anchored = anchoredBy !== null && !polarityMismatch && !identifierMismatch && !valueSwap` (`:3473`), so three belts can revoke a granted anchor — polarity (R2), identifier (R3/R4b) and **the value slot itself (V1, `wordFlip` `:401`)**.
- **D2 — the premise check only ever looked at the row that won the support slot.** A row stored under `scope: env=prod` answered `verify("gto 内存上限是 4GB", { scope: 'env=dev' })` with `substantiated: true, out_of_scope: false`: the prod row was demoted into `newer_related[]` and a **premise-less** row supplied the support at sim 0.58. Root cause: premise-aware ranking deliberately puts a scope-less row *above* a conflicting one (matching 2 > unstated 1 > clashing 0), and the old veto only read `best.scope` — so a clashing row could never sit in the slot the veto looked at. It was **unreachable code**, not a missing feature. The comparison now runs over the whole above-floor candidate set, and a clashing row that matches at least as well as the chosen support vetoes the verdict and is named in `scope_conflicts[]` (empty when the support *is* the clashing row, which exits through the same `OUT_OF_SCOPE` branch with the id in the note — and since G3 the same holds when the support's premise shares no key with the caller's: the note names the axes instead, the list stays empty). Relevance is anchored on similarity alone: entities are optional, and gating the veto on entity overlap made it inert for every entity-less store — opencode's own adapter test caught that, not reasoning. **Round eight (G1) corrected two things on this rule.** A premise stated on an *axis the caller never named* (`release=v2` against `env`/`region`) is neither agreement nor conflict — it is simply not comparable — and reading "no difference found" as "this is the caller's own premise" let such a row win the support slot **and** switch the whole scan off (`scopesComparable` `src/memory.ts:4078`, `scopeStatesCallerPremise` `:4100`, read at `:2847` and `:2934`; a non-comparable row now ranks *with* the premise-less ones, so its own premise still gets quoted in the note — **that tie was re-ruled in round nine: it let an off-axis row out-rank a premise-free general statement, so the tier is now the lowest one, see the G3 bullet below**). And the veto now has two routes side by side rather than one: the score route above, plus a same-thing route (`sameThingAnchor` `src/memory.ts:2734`) that fires when the candidate shares an `identifier` or `subject` anchor with the claim — the `entity` tier does not qualify, because `api` names a topic, not a claim. - **R1 — a wrong value written with a Chinese copula used to be stamped as support** (the dangerous direction, and the one D1's own "honest limits" bullet got wrong). Against the stored truth `gto 最大并发连接数 -> 128`, `verify("gto 最大并发连接数是 512")` returned `substantiated: true` at bge sim **0.81**, while the same claim spelled `-> 512` — and the English `probe-lang cache dir is E:\other-cache` — correctly returned `contradicted`. ## 0.3.0 (published to npm, 2026-09-20) — premise scope, duplicate merge, low-confidence fallback, sibling stores visible, fuzzy false-positive fix

Five changes from one piece of field feedback, all on one theme: **separating "looks like there is nothing" from "that is not what happened"**.

- **① Premise scope (`scope`)** — see the *Premise scope* bullet below. Beyond writes and verify, `recall(cue, { scope })` now **hard-filters** rows whose premises clash and returns `scopeExcluded`; both adapters' `memory_recall` forward `scope`.
- **② Duplicates can be merged** — `duplicates()` used to be read-only, so cleanup meant `delete`, which drops version history with it. `mergeDuplicates({ ids, into, dryRun })` (host-side: `memory_maintain merge`, in both adapters, **preview by default**) now folds the extras into a survivor: rows stay in the store, disappear from default recall, and come back with `undemote`. Entities, tags, the longer `detail` and a higher `importance` are carried over *before* the source rows retire. **The same sentence under two premises is not a duplicate**: groups now carry `mixedPremises`, which means *some pair* in the group disagrees. `merge` never folds a row whose premises clash with the survivor — those come back in `blocked[]` naming the clashing keys, while the rows that do agree are still merged; if every other row clashes, nothing is folded and `survivor` is `null`.
- **③ A below-threshold recall is no longer blank** — every hit under the floor used to render as "nothing relevant", identical in shape to an empty store. The closest trace is now surfaced as line 1 tagged `[low-confidence sim 0.31 < floor 0.32: the closest trace, not a memory — verify before asserting]`, without borrowing the row's `[VERIFIED]` / `[ASSERTED]` badge; `items[0].lowConfidence === true` covers the programmatic side. Still no guess when similarity is exactly 0, the store is empty, or `{ lowConfidenceTop1: false }` is passed. Zero-hit digests no longer backfill `[recent]` filler. `diagnostics().coverage` counts `turns / misses / guesses` for the live process.
- **④ `status` can see the other store** — DSH shards by agent id, opencode by project directory, which makes "was never stored" and "was stored in a different file" render identically. `diagnostics()` now returns `sibling_stores` (every `.db` in the directory: rows, demoted, last write, which one answered) plus `scope_rule` (the contract lives in the engine once); each adapter's `status` adds its own host `path_rule`, and `health` checks "empty here, full next door" first.
- **⑤ Fuzzy archived-match false positive fixed + adapter pass-through** — `sourceMonitor`'s fuzzy archived-revision matcher used to admit rows on cosine alone, so an unrelated subject that merely shared wording with the claim and had flipped its own value would land in `superseded_matches` and wrongly set `contested` / `stale_support`. It now requires the archived row to share an entity with the support row (unless it *is* the support row); the exact-restatement tier is unaffected. Adapters also gained: `memory_recall` forwards `scope` and returns `scopeExcluded`; `memory_remember` echoes `verify_result` / `verified_at`.

Engine + both adapters + docs shipped as **0.3.0** (**215 tests green** at that release: 163 engine + 35 DSH + 17 opencode; additive schema change). Details: [CHANGELOG.md](CHANGELOG.md).

## Features

- **Local-first**: SQLite via `node:sqlite`, per-session stores under `~/.dsh/storages/hippo-memory/`. No cloud, no network, no external services.
- **Conflict versioning**: correcting a stored value archives the old revision (`history`), never silently overwrites. The write call reports exactly what it replaced via `superseded: { id, version, summary }`.
- **Trustworthy writes (0.2.0)**: `memory_remember` echoes the nearest neighbours (`neighbours[]` with `suspectedConflict`) so a correction is never blind, and accepts `supersedes: [ids]` to explicitly retire wrong rows (`superseded_by` edge, kept for audit, excluded from recall).
- **Source monitoring**: `memory_verify` returns SUBSTANTIATED / CONTRADICTED / OUT_OF_SCOPE / WEAK_MATCH / UNSUBSTANTIATED plus evidence groups — `contradicting[]`, `newer_related[]`, `superseded_matches[]`, `scope_conflicts[]`, `stale_support` — so an old wording winning on cosine no longer hides the real, newer conclusion, and since 0.3.2 no longer certifies a claim it merely shares a topic with (a yes needs an anchor; without one you get `weak_match: true`). It reports a **raw cosine** (single best 1-NN, no importance weighting) — the same scale as `recall().hits[].similarity`, not `score`.
- **Explainable recall**: every hit carries three distinct numbers — `similarity` (raw cosine, comparable to the threshold and to `memory_verify`), `score` (ranking value: `similarity × (0.6 + 0.4·importance)`, capped at 1.0), and `relativeScore` (best hit for *this* query = 1.0) — plus `anchored` / `anchors` (0.3.2): whether anything identifiable ties this row to the cue, and which tier did it (`identifier` / `entity` / `subject` / `vocabulary` / `recency`). **`relativeScore` is relative, not a confidence scale**: the top row of every set reads exactly 1.000 whether it was found by shared identifiers or by cosine alone, so read `anchored` to tell "best match" from "closest vector neighbour". An empty result returns `reason` (`below-threshold` vs `no-candidates`), `eligible`, `bestSimilarity`, `threshold`, and `nearMisses` instead of a bare empty array. When nothing clears the floor, the digest still hands over the closest trace — labelled as a guess, not as a memory (see ③ above).
- **Literal identifier matching**: an exact token hit (`0x6070`, `D-387`, a commit sha, a version) is stronger evidence than a low cosine for a bare-identifier query, so such rows are retrieved even below the threshold and flagged `literalMatch`. Measured on a real 167-memory store over 276 identifier queries: Top-1 hit rate 10.5% → **99.6%**, MRR 0.195 → **0.998**.
- **Evidence, retraction, prospective guards (0.2.0)**: recheckable provenance (`verify_cmd` / `verify_expect` / `verify_artifact` + `verify_result`) with a 30-day freshness TTL — a fresh `[VERIFIED]` row can only be retired by other passing evidence, otherwise it renders `[ASSERTED]`; `retracts` marks a do-not-repeat retraction; `guard_trigger` / `guard_action` register a prospective trigger that is injected as `[GUARD]` when the cue matches.
- **Premise scope (`scope`, 0.3.0)**: a sentence that is true under one measurement setup and false under another used to collapse into a single flat summary, so `verify` blessed the old-comparator answer for a new-comparator question (the field report's real case: `P(X==disp)` ≈ independence baseline under "records land at the instruction start" vs **0.84388** under "the record's own `disp` field" — the only partial solution on that research line). A row can now state its premises as `key=value` segments (`population=all records; comparator=instruction start`), compared **structurally, with no new similarity threshold** (`diagnostics().thresholds` unchanged) — keyed premises compare on the keys both sides name, and since 0.3.2 a premise written **without a key** (`us-east`, `first 4096 rows`) is no longer invisible: bare segments collect under an internal `@premise` key so two different bare premises veto each other instead of silently standing in for one another; values stay compatible on subset or Jaccard ≥ 0.5, and an unstated premise never counts as a contradiction. A clashing write stays its own trace (`different-scope:` warning) instead of overriding; `sourceMonitor(claim, { scope })` prefers the trace stated under the caller's premises, returns `out_of_scope: true` on a disagreement, and appends a `CONDITIONAL SCOPE` note when the support's premise was not checked (0.3.2 widened that comparison from the support row alone to the whole above-floor candidate set — see the 0.3.2 section; in that same 0.3.2, G1 stopped reading a premise keyed on an axis the caller never named as agreement — it is **not comparable** — and G3 wired that predicate into the affirm itself, so a support row that speaks nobody's conditions can no longer stamp `substantiated: true` (`scopeCanSupport`, `src/memory.ts:4124`; the rank band became matching 2 > unstated 1 > clashing 0 > not-comparable −1, the last tier having been tied with "unstated" by G1 and re-ruled by #G3-121); 0.3.2 also scopes `newer_related[]` / `contradicting[]` / `stale_support` to the premise actually asked about, so a newer row stated under a foreign premise no longer makes the current answer look stale). Surfaced as `[scope: …]` in composed context and on recall hits. Old stores gain the column automatically (`ensureColumns()`), no migration step. **G4 (also 0.3.2) removed the reverse rule**: a re-tell that carried a premise while the stored row carried none used to write that premise onto the original row (`premiseFill()`), and that branch returned `outcome: 'none'` — no version bump, no `history` — while `scope` is exactly what decides *for whom* a row speaks: a premise-free row is a general statement that answers every caller, a keyed one answers only callers inside its condition. Measured on 7 shapes: 4 were silently narrowed and all 4 lost read-side coverage (`.hippo/probe-g4-round28.txt`). **Four** retirement sites now refuse it — the three rehearsal branches plus the similarity-driven `brink` arm, because round eleven's RR1 measured exactly "wired into three of four" — keeping the general row general, storing the conditioned re-tell as its own trace and returning a `premise-narrowing:` warning; to actually narrow a row, say so with `supersedes: [id]` or `update()`, which bump the version and archive the old premise. On the read side a premise-free row that **verbatim** restates the claim (`isVerbatimRestatement`, `src/memory.ts:4143`) still substantiates a caller who states a contradicting premise — it is the same sentence, merely unconditioned — while the keyed twin is reported in `scope_conflicts[]` and named in the note; a *different* sentence is vetoed as before (that exemption is a deliberate carve-out of the D2 rule, tested both ways, and **its boundary is measured rather than assumed**: reworded claims in the hashing space never even clear the 0.32 recall floor — 0.31 / 0.26 — so the non-exempt side can only be pinned with a stub embedder). **Round eleven's RR2 added the seat rule**: a premise-free row keeps its rank band only when it *is* evidence about this claim — `sameThingAnchor` (`src/memory.ts:2734`) firing on the identifier or subject tier, or verbatim identity — otherwise it drops to the bottom band with the rows that answer nobody, where similarity decides (`src/memory.ts:2869`); a premise-free row about **another subject** may no longer take the support slot from the trace that *is* the caller's sentence, and its vacuously-admissible premise is precisely what used to switch the veto scan off. The demotion is bounded by a guard in the same landscape: a premise-free row that *states* the claim keeps the seat. **RR3 fixed the note's attribution, not the flag**: `stale_support` has two causes, only the `newer_related` one may point at `newer_related`, staleness earned by an archived revision now says so in its own words (`src/memory.ts:3324`), and the `CONTESTED` sentence lists only the arrays that are populated (`src/memory.ts:3384`). The same predicate is wired into all three consumers — write (`narrowsPremiseFree`, `src/memory.ts:941`), read (`isVerbatimRestatement` plus the seat rule) and merge (`premiseAgrees`, `src/memory.ts:4161`) — and after RR1 into **every** retirement site rather than three of them.
- **Duplicate reporting & merging**: `duplicates()` is a read-only report of restatements across kinds (ignoring the consolidation `FACT: ` wrapper), with each row's `scope` and a per-group `mixedPremises` flag. **Two channels, and the group says which one found it** (0.3.2): `by: 'text'` for normalised-verbatim restatements, and `by: 'vector'` for paraphrases that reach `nearDuplicateThreshold` (default 0.92, exposed in `stats()`), clustered with union-find so an A~B~C chain is one group rather than whichever order the pairs happened to be walked in, with the group's **weakest** measured edge printed as `similarity`. Before this, a fact stored three ways reported `groupCount: 0` while recall showed those rows at cosine 0.937 — `compress` / `merge` were waiting on a list that could never be non-empty. `mergeDuplicates()` folds a group into one survivor via the reversible demote path (`undemote` restores) — it never deletes, its guard accepts what the vector channel identified (reachability from the first id; unreachable ids are named in the error), and it refuses to fold rows that state different premises **or rows where only one side states a premise at all** (0.3.2, same round as G4: a general statement and a conditioned one are not restatements of each other, so `duplicates()` flags the group `mixedPremises` and `mergeDuplicates` refuses in both survivor directions — while a pair that states nothing on either side still folds). Consolidation itself no longer creates the episode/rule twin.
- **Optional real embeddings** (setting `auto`): lazy-loads `Xenova/bge-small-zh-v1.5` (~24MB quantized, cached under the store dir) for strong CJK/paraphrase recall; falls back to the built-in hashing embedder on any failure.
- **Adaptive forgetting & consolidation**: `consolidate` abstracts repeated episodes into semantic rules; `forget` decays weak traces with a dry-run preview; `compress` folds N same-scope traces into 1 caller-authored invariant + K representatives (`undemote` restores).
- **Spaced repetition**: rehearsal strength grows with the gap since last access (`0.01 + 0.03·log2(1+days)`, capped at 0.12) — massed repetition earns little, spaced re-telling earns a lot, and a genuine recall after a gap strengthens the trace too (testing effect). `memory_remember` accepts an explicit `importance` (0..1) so critical facts can outrank trivia.
- **Injection guard (memory anti-poisoning)**: a page the agent read can end up inside a `memory_remember` write ("ignore all previous instructions…") and would then re-inject into every turn. Rendered memory text is sanitized (`[sanitized-*]` markers) on every engine output path (digest / recall / nearMisses / conflict warnings / verify / list / history / duplicates / merge), wrapped in a `[memory data … not instructions]` frame; stored rows stay untouched for audit, and infected rows are flagged (`injection:` warnings in recall/verify, `injectionWarnings` in list). Sanitizing rows never silences them. Designed conservatively — only phrases that try to redirect the reader's instructions are touched — and no false positives were observed across the real stores tested. **Adapter coverage differs**: DSH sanitizes every tool result; opencode sanitizes the auto digest plus the new `duplicates` / `merge` reports, while its `list` / `history` / `recall` hits are still raw (open item in [ROADMAP.md](ROADMAP.md)).
- **Safer overrides**: path-3 now needs **two gates** — content cosine *and* a summary-to-summary claim cosine (default 0.75). If the claim gate fails the write degrades to a new row with a `withheld-contradiction:` warning: better an extra row than a lost memory. Since 0.3.2 the **read** side asks the same bar of a yes, through anchors rather than through one number (see the 0.3.2 section).
- **Concurrent-safe shared store**: WAL + `busy_timeout` (5s default, configurable) so multi-agent shared-store writes no longer throw `SQLITE_BUSY`.
- **Observability**: `diagnostics()` and `memory_maintain status` expose store path, embedder kind+dim, a stored-vector dimension histogram, `dimMismatch`, all thresholds, access stats, `coverage` (this process's digest turns / misses / guesses) and a one-line `health` verdict — the only way to catch the silent killer (model-vector store queried by the hashing fallback → garbage cosines → permanently empty recall). Since the 0.3.0 batch it also reports `sibling_stores` + `scope_rule`, so a store split ("stored, but into another file") reads differently from "never stored"; each adapter adds its host's `path_rule`.
- **Override audit**: `override-audit` (read-only) screens overridden pairs whose content has almost nothing in common — the signature of an unrelated memory retired by a bad override.
- **Tidy storage**: stores open lazily — read-only traffic stays in memory, the `.db` appears only on first write, and `memory_maintain prune` sweeps empty leftovers.
- **GUI card**: enable/disable live, context limit, shared store, embedding mode, recall threshold.
- **One-shot migration**: enabling `auto` re-embeds legacy hash rows with the model automatically (persisted marker, runs once); `memory_maintain status` reports model state.

## Engine quick start

```js
import { HippoMemory } from 'hippo-memory-core';

const mem = new HippoMemory({ dbPath: './agent-memory.db' });
await mem.remember({ kind: 'semantic', summary: 'billing service database -> postgres', source: 'user' });
const { items, context } = await mem.composeContext('fix billing connection', { limit: 5 });
// items[0].lowConfidence === true -> that line is the closest trace, not a memory
const v = await mem.sourceMonitor('billing service database is postgres', {
  scope: 'deployment=prod',           // check the premise, not just the sentence
});
// v.out_of_scope === true -> the support was stated under different premises
// v.scope_conflicts        -> clashing-premise rows that vetoed it without winning the support slot
//                              (empty when the veto is the support itself, and — since G3 — also when
//                              the support sits on an axis you never named: that is "not comparable",
//                              not a clash, so its id and both sides' keys are printed in the note)
// v.weak_match === true    -> topically nearby, no anchor: a lead to re-check, NOT evidence
// v.substantiated ? 'safe to assert' : 'answer: not in my memory'

const group = mem.duplicates().groups.find((g) => !g.mixedPremises);
await mem.mergeDuplicates({ ids: group.memories.map((m) => m.id), dryRun: true });  // preview
// apply with dryRun: false; extras are demoted, restorable via mem.undemote(ids)

mem.diagnostics().sibling_stores;   // every .db next to this one: rows / demoted / lastWrite / current
mem.diagnostics().coverage;         // { turns, misses, guesses, scope: 'process' }
```

`v.substantiated ? 'safe to assert' : 'answer: not in my memory'` — and `v.weak_match` is the same answer: a topically nearby trace is not evidence.

Runtime: Node ≥ 22.5 (`node:sqlite`) **or** Bun (`bun:sqlite`) — the driver is auto-detected at load time, so the same package also runs inside Bun hosts such as **opencode**. Tests: `npm test` (**219 engine + 54 DSH + 18 opencode = 291**, all green on this machine). Bench: `npm run bench`.
