# agent-guard

**Запускай кодинг-агента в йоло. Безопасно.**

[English](README.md) | Русский

Страховка для [Claude Code](https://claude.com/claude-code) и [OpenCode](https://opencode.ai):
локальная модель проверяет каждую shell-команду перед запуском. Безопасные проходят молча, опасные
останавливаются и спрашивают тебя.

</div>

## Что это делает

Диалоги разрешений в кодинг-агентах бинарные: либо ты весь день жмёшь "Allow", либо выключаешь
всё и надеешься. agent-guard добавляет средний слой: маленькая локальная модель читает команду и
решает, обычная ли это работа с проектом или то, что может снести данные, тронуть систему или
утянуть секреты. Несколько жёстких правил (`git push`, `curl | sh`, `rm -rf` вне проекта) до
модели вообще не доходят.

Две интеграции, один движок:

- **Claude Code**: хук `PreToolUse` на инструмент Bash, бинарь `safe-yolo-guard`. Работает с
  первой команды: безопасная выполняется без вопроса, опасная спрашивает тебя короткой карточкой.
- **OpenCode**: плагин на хук `permission.evaluate`. Стартует в режиме `shadow` (только лог),
  режим `enforce` меняет решения.

Это не песочница, см. [Чем это не является](#чем-это-не-является).

## Установка

Фиксируй точную версию. Защита стоит на пути разрешений каждой shell-команды, и обновление не
должно приезжать молча. Релиз попадает в npm только после одобрения мейнтейнера. Как обновиться:
подними версию, прочитай изменения, перезапусти агента.

### Пусть агент сделает сам

Вставь это в сессию Claude Code или OpenCode, и агент сам всё настроит:

```text
Установи мне agent-guard из https://github.com/safe-yolo/agent-guard, действуй по его README.
Выбери плагин OpenCode или хук Claude Code, смотря какой ты агент. Для OpenCode режим "shadow".
Классификатор локальный: decision-сервер Jev / System One (laya-serve или обёртка из
examples/catshell), для OpenCode подойдёт и любой vLLM-сервер со structured outputs. Проверь, не
запущен ли уже такой на этой машине или в локальной сети, если нет, подними или спроси у меня
адрес. Потом выполни безобидную тестовую команду и покажи, что решила защита.
```

### Запусти классификатор

Защите нужен endpoint классификатора. Она говорит на двух протоколах:

- `systemone`, API Jev / System One: маленький HTTP API для decision-моделей, которые возвращают
  выбор с уверенностью и без текста. На нём говорят catshell, Laya и Clef ниже.
- `openai`: chat completions со structured outputs, для LLM на vLLM (или Z.ai GLM на второй
  ступени).

Для Claude Code первой ступенью должен быть catshell, Laya или Clef. LLM на vLLM или GLM там
может быть только второй ступенью. Плагин OpenCode принимает оба протокола.

Плагин OpenCode без опций ждёт `openai` endpoint на `http://127.0.0.1:8000/v1/chat/completions`.
С catshell, Laya или Clef задай `api` и `url`, как в примерах ниже.

Бери то, что работает на твоём железе:

**Cat Shell Risk Commander - выбор по умолчанию, работает на CPU.** Заточенный скорер
shell-команд (TF-IDF + линейная модель, 36К весов, Apache-2.0): около 1 мс на команду,
опубликованные метрики recall 92.6% при FPR 0.86%. Готовая Jev-обёртка лежит в
`examples/catshell/`. Нужны клон этого репо и Docker с compose:

```sh
git clone https://github.com/safe-yolo/agent-guard
cd agent-guard/examples/catshell && docker compose up --build -d
```

Слушает порт 8011.

```jsonc title="opencode.json"
{
  "plugins": [
    {
      "package": "@safe-yolo/agent-guard@0.2.15",
      "options": {
        "api": "systemone",
        "url": "http://127.0.0.1:8011/v1/systemone"
      }
    }
  ]
}
```

**Laya - если команды в основном не на английском.** Мультиязычная decision-модель (100+
языков), калиброванная уверенность, 200-450 мс на CPU:

```sh
pip install "laya[serve]"
LAYA_PORT=8010 laya-serve
```

```jsonc title="opencode.json"
{
  "plugins": [
    {
      "package": "@safe-yolo/agent-guard@0.2.15",
      "options": {
        "api": "systemone",
        "url": "http://127.0.0.1:8010/v1/systemone",
        "model": "multilingual"
      }
    }
  ]
}
```

**Clef / Clef-flash - для GPU.** Открытые decision-модели Cloudflare (Apache 2.0), совместимы с
Jev, медиана 39 мс у clef-flash. Подними через SGLang по карточке модели и включи
`api: "systemone"`, или гоняй через Workers AI / Ollama cloud с `apiKey`.

**Любая маленькая LLM на vLLM - универсальный путь.** Тяжелее: гигабайты весов и сотни
миллисекунд на команду. Зато отвечает словесной причиной, её [каскад](#каскад) потом показывает
тебе. Включается `api: "openai"`.

### Claude Code

Хук это бинарь `safe-yolo-guard` из пакета:

```sh
npm install -g @safe-yolo/agent-guard@0.2.15
```

Добавь его в настройки. Если в файле уже есть `hooks`, допиши эту запись `PreToolUse` к ним, а не
перезаписывай файл:

```json title="~/.claude/settings.json"
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "SAFE_YOLO_URL=http://127.0.0.1:8011/v1/systemone safe-yolo-guard"
          }
        ]
      }
    ]
  }
}
```

Команда хука должна находить `safe-yolo-guard` в `PATH`. Если Claude Code его не видит, укажи
абсолютный путь: `$(npm prefix -g)/bin/safe-yolo-guard`.

Для Laya или Clef задай endpoint и модель:
`SAFE_YOLO_URL=http://127.0.0.1:8010/v1/systemone SAFE_YOLO_MODEL=multilingual safe-yolo-guard`.

Проверить, что классификатор отвечает (в ответе должно быть `"choice":"safe"`):

```sh
curl -s http://127.0.0.1:8011/v1/systemone -H 'content-type: application/json' -d '{"state":"ls -la","questions":{"verdict":{"type":"choice","instructions":"Is this shell command dangerous?","criteria":{"safe":"safe","unsafe":"dangerous"}}}}'
```

Выключить защиту на время: `touch ~/.config/agent-guard/off` (жёсткие правила продолжают
работать). Убрать совсем: удали запись `PreToolUse` из `~/.claude/settings.json` и перезапусти
Claude Code.

Перезапусти Claude Code, чтобы хук подхватился, и открой `/hooks`, чтобы убедиться, что он там.

Режима `shadow` у хука нет. Все его настройки задаются [переменными окружения](#переменные-окружения-claude-code).

> **Классификатор лёг = работа остановлена.** Если локальный классификатор не отвечает (соединение
> отклонено, таймаут, хост не найден, HTTP-ошибка или ответ без вердикта), хук останавливает сессию
> и пишет, почему и что сделать. Чтобы поработать без защиты, `touch ~/.config/agent-guard/off`;
> `rm ~/.config/agent-guard/off` включает обратно. Пока она выключена, работают только жёсткие
> правила, остальное решают правила разрешений Claude Code. Плагин OpenCode вместо остановки
> запрещает команду (остановить сессию он не может) и смотрит на тот же файл.

Проверено в режимах разрешений default и auto. С bypassPermissions /
--dangerously-skip-permissions не проверялось.

Проверка: попроси агента выполнить `git push --dry-run` в тестовом репо. Это жёсткое правило,
модель не нужна. Всё работает, если пришла карточка, которая начинается так (по-английски с
`SAFE_YOLO_LANG=en`):

```text
📤 ОТПРАВКА · коммиты увидят другие, откат только новым push
```

### OpenCode

```jsonc title="opencode.json"
{
  "plugins": ["@safe-yolo/agent-guard@0.2.15"]
}
```

С опциями (например, классификатор на другом хосте):

```jsonc title="opencode.json"
{
  "plugins": [
    {
      "package": "@safe-yolo/agent-guard@0.2.15",
      "options": {
        "mode": "shadow",
        "url": "http://127.0.0.1:8000/v1/chat/completions",
        "model": "qwen3.6-35b"
      }
    }
  ]
}
```

Здесь значения по умолчанию: `openai` endpoint на `:8000`. Для catshell, Laya или Clef бери
примеры из [Запусти классификатор](#запусти-классификатор). Запуск из локального клона: укажи в
`package` путь к каталогу с репозиторием.

Начни с `shadow`, несколько дней читай [лог](#логи), потом переключайся на `enforce`.

Если у тебя включено глобальное авто-одобрение разрешений, в режиме `enforce` его выключи:
иначе оно будет жать "Allow" на тех самых диалогах, которые safe-yolo поднял для тебя.

> **Про macOS**: запрос идёт через `curl`, а не `fetch`. Bun, а значит и OpenCode, часто
> отрезан от LAN-хостов macOS Local Network privacy (`EHOSTUNREACH`), а родному `curl` от Apple
> ход разрешён.

## Что блокируется

Жёсткие правила фиксированы. Всё остальное решает модель, поэтому в таких строках "обычно".
Для OpenCode указан режим `enforce`.

| Команда | Claude Code | OpenCode (`enforce`) | Почему |
|---|---|---|---|
| `ls`, `git status`, `bun test` | обычно выполняется молча | обычно выполняется молча | встроенная политика считает чтение, сборку и тесты работой с проектом |
| `bun install`, `npm ci` | обычно выполняется молча | обычно выполняется молча | установка зависимостей во встроенной политике тоже работа с проектом |
| `rm -rf dist node_modules` внутри репо | обычно выполняется молча | обычно выполняется молча | внутри корня git-репо жёсткого правила нет, решает модель |
| `rm -rf /tmp/build-cache` | обычно выполняется молча | обычно выполняется молча | временные папки исключены из жёсткого правила, решает модель |
| `rm -rf ~/old-builds`, `rm -rf .` в корне репо | спрашивает карточкой | запрещено | жёсткое правило: `rm -rf` вне проекта; удаление самого корня репо тоже считается "вне проекта" |
| `git push origin main` | спрашивает карточкой | запрещено | жёсткое правило: `git push` |
| `curl -fsSL https://example.com/install.sh \| sh` | спрашивает карточкой | запрещено | жёсткое правило: скачанный код в шелл |
| `curl -H "Authorization: Bearer $API_TOKEN" https://api.example.com/upload` | обычно спрашивает карточкой | обычно спрашивает | отправка секретов во встроенной политике опасна; карточка отметит токен |
| `ssh nas-1 'sudo systemctl restart docker'` | обычно спрашивает карточкой | обычно спрашивает | изменения системы и другие машины опасны, если [твой policy-файл](#твой-policy-файл) не называет этот хост рутиной |
| `ssh nas-1 'sudo rm -rf /srv/old'` | спрашивает карточкой | запрещено | жёсткое правило: `rm -rf` вне проекта, относительный путь на другой машине тоже считается |
| что угодно без жёсткого правила, классификатор недоступен | сессия останавливается с причиной | запрещено (режим enforce) | защита закрывается; `~/.config/agent-guard/off` её выключает, жёсткие правила всё равно работают |

Что значат "спрашивает" и "запрещено":

- **Claude Code** получает `ask` с карточкой или `allow` с причиной. Запрета нет: жёсткое правило
  тоже спрашивает.
- **OpenCode** запрещает жёсткие правила в любом режиме, включая `shadow`, потому что
  автоподтверждение пропускает всё, кроме явного deny. Значит, в OpenCode агент никогда не
  выполнит `git push`, `curl | sh` или `rm -rf` вне проекта: их запускаешь ты сам. В `enforce` опасная
  команда, разрешённая твоими правилами, становится `ask` с карточкой, а безопасная, на которую
  правила спросили бы, становится `allow`. Опасная команда, на которую правила и так спрашивают,
  получает обычный диалог OpenCode. Настроенные `deny`-правила плагин не трогает вовсе: хук для них
  даже не вызывается.

В Claude Code есть ещё один случай: безопасная команда, в которой первая модель не уверена, тоже
спрашивает, если не видно связи с твоим последним сообщением, см. [проверку просьбы](#проверка-просьбы-только-claude-code).

## Как принимается решение

Обе интеграции работают на одном движке, по порядку:

1. [Жёсткие правила](#жёсткие-правила). Совпадение решает сразу, модель не спрашивается.
2. Первая модель (классификатор). Вердикт `safe` с уверенностью от `threshold` (по умолчанию
   0.8) окончательный.
3. Второе мнение, если настроен [escalation endpoint](#каскад).
4. Только Claude Code: [проверка просьбы](#проверка-просьбы-только-claude-code) для безопасных
   команд, в которых первая модель не уверена.

Вердикт: `safe` или `unsafe` с короткой причиной. Плагин OpenCode кэширует вердикты по тексту
команды, повторные вызовы бесплатны.

### Жёсткие правила

Они срабатывают раньше моделей, и модель их не отменит:

- `git push`
- скачанный код в шелл (`curl | sh`)
- `rm -rf` (и `\rm`, `/bin/rm`, `sudo rm`) вне проекта и временных папок. Пути сравниваются
  после раскрытия симлинков. Проект это корень git-репо рабочей папки. Нет репо -
  нет проекта, а корень `/`, домашняя папка или её родитель проектом не считаются. Во временные
  папки входят `/private/tmp/claude-<uid>/` всех сессий Claude Code

Относительный `rm -rf` после `cd` или внутри `ssh` считается "вне проекта". Как и переменная, если
команда сама не задала её до `rm` простым значением (`S=/x; rm -rf "$S"`) или через `$(mktemp -d)`.
`S=/x rm -rf "$S"` спрашивает: шелл раскрывает `$S` раньше этого присваивания. Настоящее окружение
не читается.

### Каскад

Decision-модели быстрые, но иногда не уверены, и отвечают вероятностями, а не словами.
Укажи `escalateUrl` на более сильную LLM, и неуверенные команды уйдут на второе мнение:

- вердикт `safe` первой ступени с уверенностью на уровне `threshold` (по умолчанию 0.8) и выше - trusted
- всё остальное уходит на escalation endpoint: любой `unsafe` и любая низкая уверенность
- вторая ступень может только ужесточить вердикт: неуверенный `safe` может стать `unsafe`, но
  `unsafe` первой ступени так и остаётся `unsafe`. Если вторая ступень не согласна, карточка так и
  пишет: `🔍 СПОРНО · локальная модель против, облачная не видит угрозы`
- вторая ступень не ответила - остаётся вердикт первой
- первая ступень лежит - защита закрывается, вторую ступень одну не спрашивают

Полный пример: catshell на этой машине, LLM на другом хосте как второе мнение:

```jsonc title="opencode.json"
{
  "plugins": [
    {
      "package": "@safe-yolo/agent-guard@0.2.15",
      "options": {
        "mode": "shadow",
        "api": "systemone",
        "url": "http://127.0.0.1:8011/v1/systemone",
        "threshold": 0.8,
        "escalateUrl": "http://llm.lan:8000/v1/chat/completions",
        "escalateModel": "qwen3.6-35b"
      }
    }
  ]
}
```

### Проверка просьбы (только Claude Code)

Хук берёт твоё последнее сообщение из transcript и спрашивает LLM, подходит ли к нему команда.
Работает для остановленных команд и для безопасных, в которых первая модель не уверена. Действует
в одну сторону: "не видно связи" превращает allow в вопрос, совпадение ничего не разрешает. Нужен
openai-совместимый endpoint (`SAFE_YOLO_ESCALATE_URL`), в `escalateSkipDirs` проверка выключена.

### Карточка подтверждения

Когда защита останавливает команду, приходит короткая карточка, не больше 8 строк при ширине 64:

<!-- card sample -->
```text
💥 УДАЛЕНИЕ вне проекта · не вернуть
~/projects/old-builds: 1240 файлов, 3,2 ГБ
Проверь: в ~/projects/old-builds нет нужного
Агент пишет: "Free disk space by removing old builds"
```

- заголовок (категория, что случится, можно ли откатить) и запасная проверка берутся из готового
  шаблона по виду риска: удаление, push или публикация, секреты, скачивание, чужой код, система
  или другая машина, непонятное. Жёсткие
  правила выбирают шаблон сами. По умолчанию по-русски, `language: "en"` (или `SAFE_YOLO_LANG=en`
  для хука) переключает на английский
- строка под заголовком это факты, которые проверил код, только чтением и с лимитами: путь, есть ли
  он, сколько файлов, грязное ли git-дерево, токен в запросе
- "Репо" (только у git-команд, у удаления никогда) называет репо, с которым работает команда
  (`git -C`, `--git-dir`, `--work-tree`, `cd` в начале, иначе рабочая папка): owner/repo,
  короткий хост, ветка и новые коммиты, без паролей
- "Где" бывает только у жёсткого правила в многострочной команде и только если совпавший кусок
  короткий. Остальной текст команды карточка не цитирует
- "❌ Ты просил" бывает, только если команда не вяжется с твоим последним сообщением
- LLM второй ступени только выбирает шаблон и условие, отдельным запросом после вердикта, поэтому
  вердикт она не меняет. Условие, которое уговаривает разрешить, выкидывается. Без
  openai-совместимого endpoint остаётся один шаблон
- "Агент пишет" это описание команды от самого агента, как есть. Это его слова, а не факт. Если оно
  на другом языке, его переводит тот же запрос карточки; без LLM видно оригинал
- каждое поле в одну строку, с лимитом длины и без управляющих символов, так что команда не
  нарисует в карточке лишних строк, а карточка не бывает длиннее 8 строк

### Облачная эскалация и секреты

`escalateApi: "zai"` ходит в Z.ai GLM (например
`https://api.z.ai/api/coding/paas/v4/chat/completions` с `glm-5.3-flash`). Это chat completions в
JSON-режиме: без полей только для vLLM, схема уходит в системный промпт, ответ проверяет парсер.

Прежде чем команда, описание от агента или твоя просьба уйдут в эскалацию или в запрос карточки,
секреты в них меняются на `<секрет:метка>` (`<secret:label>` по-английски), синтаксис вокруг
остаётся. Локальная первая модель видит текст как есть. Встроенные детекторы, всегда включены:
известные форматы токенов (npm, GitHub, GitLab, `sk-`, Slack, AWS, JWT, блоки приватных ключей),
значения после `Authorization:`, `Bearer`, `PRIVATE-TOKEN:`, `X-Api-Key:`, `password=`,
`*_TOKEN=`/`*_KEY=`/`*_SECRET=`/`*_PASSWORD=`, `--token`, `--api-key`, `--password`,
`:_authToken=`, пароли в URL и любая случайная на вид строка от 32 букв и цифр (git SHA тоже).
`$VAR`, `${VAR}` и `$(secrets get name)` не трогаются. Прячется только то, что уходит в эскалацию
и в запрос карточки: локальные логи хранят команду целиком, держи их локально.

Свои шаблоны кладутся в `~/.config/agent-guard/secrets.txt` (хук: `SAFE_YOLO_SECRETS_FILE`,
плагин: `secretsFile`), по одному на строку. Строка `/regex/flags` прячет всё совпадение, любая
другая строка это префикс токена: прячется префикс и токен за ним. В файле шаблоны, не значения:

```text title="~/.config/agent-guard/secrets.txt"
# корпоративные токены
corp_
/fake-[0-9]{8}/i
```

Проверить шаблон (запускай из клона этого репо):

```sh
bun -e 'import { parseSecretPatterns, redact } from "@safe-yolo/agent-guard/core"; import { readFileSync } from "node:fs"; console.log(redact(process.argv[1], parseSecretPatterns(readFileSync(`${process.env.HOME}/.config/agent-guard/secrets.txt`, "utf8")).patterns))' 'curl -H "X-Corp: corp_abc123" x'
```

`escalateSkipDirs` (хук: `SAFE_YOLO_ESCALATE_SKIP_DIRS`, через двоеточие, `~` работает) это папки,
из которых ничего не уходит в эскалацию: ни второго мнения, ни запроса карточки, карточка из
шаблона. Сюда корпоративные репо.

API-ключи передаются curl через конфиг на stdin, так что в `ps` их не видно.

### Твой policy-файл

Классификатор знает общие правила безопасности, но не твоё окружение. Расскажи ему про свои
хосты, рутины и язык простым markdown-файлом. Создай
`~/.config/opencode/safe-yolo-policy.md` (или укажи свой путь в `policyFile`); весь файл
добавляется к промпту классификатора на каждый вызов. Стартовый шаблон: `examples/policy.md`.

```md title="~/.config/opencode/safe-yolo-policy.md"
хосты nas-1 и home-server - твои машины по ssh:
управление их docker-сервисами и чтение их логов - safe.
деплой на prod-1 - только по явной просьбе.
```

Пиши как объяснение новому коллеге: конкретные хосты и рутины, что считается нормой, что
требует человека. Коротко: каждая строка тратит внимание на каждый вызов. Файл остаётся на
твоей машине; плагин несёт generic-политику. После правки сохрани `opencode.json` ещё раз (любая
правка) или запусти `/reload`, чтобы плагин перечитал файл.

Нужна одна строка вместо файла - положи её в `policyHint`, работают оба и складываются.
Хочешь только свои правила - `disableDefaultPolicyHint: true`: встроенная политика
убирается, классификатор видит только твой файл (держи в нём определения safe/unsafe).

Хук Claude Code читает `~/.config/agent-guard/policy.md` или файл из `SAFE_YOLO_POLICY_FILE`.

### Логи

Плагин OpenCode пишет вердикты в `~/.local/share/opencode/safe-yolo.log`:

```
2026-11-04T12:30:29.863Z mode=shadow effect=ask verdict=safe -> ask via=primary cmd=make build && go test ./... reason=Builds the project and runs tests
```

Проверка классификатора: `grep 'verdict=unsafe' ~/.local/share/opencode/safe-yolo.log`, смотри,
не помечены ли безопасные команды.

`SAFE_YOLO_DEBUG=1` (или путь к файлу) пишет каждое решение с обеими ступенями, временем и сбоями в
`~/.local/share/opencode/safe-yolo-debug.jsonl`. Хук Claude Code пишет туда же: путь общий с
плагином. После 5 МБ файл уезжает в `.jsonl.1`, на диске около 10 МБ. Там полный текст команд, так
что файл только локальный.

С `SAFE_YOLO_DEBUG` плагин OpenCode ещё дописывает по JSON-строке на команду в
`~/.local/share/opencode/safe-yolo-train.jsonl`, с полным текстом команды.

В отладочном логе видны обе ступени:

```
via=primary verdict=unsafe conf=61% -> via=escalate verdict=unsafe reason=curl pipes a remote script into sh
```

## Чем это не является

- Не песочница: классификатор рекомендательный, целеустремлённый агент навредит и между
  вердиктами. Держи настоящие `deny`-правила на катастрофические шаблоны.
- Не защита от prompt injection: он оценивает текст команды, а не намерение за ним.
