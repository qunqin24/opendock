Прямые сообщения между подагентами одной сессии [opencode](https://opencode.ai): главному агенту больше не нужно носить каждый факт от одного подагента к другому.

![Два фоновых подагента: coder пишет через crew_send, researcher читает письмо на следующем шаге, главный агент тоже получает записку](../media/demo.gif)

Два подагента, работающие одновременно, часто нуждаются в одном факте друг от друга: имя интерфейса, который один только что создал, файл, которого другому нельзя трогать, находка, меняющая шаг другого. Без плагина этот факт попадает в отчёт, главный агент его читает и передаёт дальше: медленно, и это засоряет его контекст. С плагином coder пишет tester'у напрямую.

## Что добавляет

| Инструмент | Что делает |
|---|---|
| `crew_list` | Состав команды: главный агент и запущенные им подагенты, короткие имена (`coder`, `coder-2`, `tester`...), задача, работает ли ещё. |
| `crew_send` | `{ to, text }`: письмо одному участнику (`to` = короткое имя, id сессии, `lead`) или всем работающим подагентам команды (`to` = `all`). |

Получатель читает письмо на **следующем своём шаге**: работающего агента письмо не прерывает, ответа никто не ждёт, поэтому два агента не могут заблокировать друг друга. В обёртке письма сказано, от кого оно и что оно от другого агента, а не от пользователя.

Правила:

- **Закончившему** подагенту писать нельзя: письмо запустило бы его снова, и его отчёт пришёл бы главному второй раз. Отправителю предлагается написать `lead` или упомянуть это в отчёте.
- Письмо **простаивающему** главному агенту (например, он ждёт фоновых подагентов) лежит в его очереди и читается при следующем его запуске, обычно когда его будит очередной отчёт. Настройка `wakeLead` будит сразу.
- Письма ходят только внутри одного дерева: главный агент и его прямые подагенты.

## Установка

Через менеджер плагинов opencode (из npm или прямо с GitHub):

```sh
opencode plugin add opencode-crew-mail
opencode plugin add git+https://github.com/retretor/opencode-crew-mail.git
```

Или вручную: скопируйте `crew-mail.js` в папку плагинов opencode (`~/.config/opencode/plugins/`) и перезапустите opencode.

В промпт главного агента полезно добавить строку, например:

> Подагенты, которые работают одновременно, могут писать друг другу через `crew_send` (см. `crew_list`). В задании скажи им, кто ещё работает в это время и над чем.

Если у вас есть плагин, который пропускает только известные ему инструменты, добавьте в его список `crew_list` и `crew_send`. Запретить инструменты агенту можно обычными правами в его файле или настройкой `agents`.

## Настройки

Необязательный файл `crew-mail.json` рядом с `opencode.json`, пример: [crew-mail.example.json](../../crew-mail.example.json). Ключи и значения по умолчанию описаны в [README](../../README.md#settings): длина письма, число писем на сессию и на пару агентов за окно времени, будить ли главного агента, копия писем главному агенту, кому разрешены инструменты, писать ли текст писем в журнал.

Журнал: `<папка данных>/opencode/log/crew-mail.log`, одна строка JSON на письмо или отказ. Сетевых соединений плагин не открывает.

## Безопасность

Письмо пишет модель. Агент, прочитавший что-то вредное (страницу, файл), может передать инструкции другому агенту. Обёртка предупреждает получателя, но это подсказка модели, а не барьер: держите остальную защиту (права, песочницу) для всех агентов, не только для главного.

## Совместимость и тесты

opencode 2.2 и новее (плагинный API V2). Проверено на opencode 2.2.3, Windows 10, Node 24. Без зависимостей.

```powershell
node --test test/unit.test.mjs
$env:CREW_MAIL_E2E = "1"; node --test test/unit.test.mjs test/e2e.test.mjs
```

Сквозной тест запускает настоящий `opencode serve` во временных папках с поддельной моделью по сценарию (без провайдера, аккаунта и сети). Ваши настройки и сессии opencode он не трогает.
